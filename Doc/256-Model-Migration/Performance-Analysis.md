## 2. 추론 속도

### 보드 관측값 (STM32N6570-DK)

| 상태 | 추론 시간 | 비고 |
|------|:---------:|------|
| 192 int8 per-channel (stock prebuilt) | ~18 ms | 정상 기준선 |
| 256 int8 per-channel (fix 전) | ~451 ms | hyperRAM 스필오버 — 비정상 |
| 256 int8 per-tensor (참고) | ~751 ms | SW fallback epoch 다수 — 채택 안 됨 |
| **256 int8 per-channel (fix 후)** | **~45 ms** | **최종 채택 상태** |

> 관측값이 ModelZoo 참조값(35.50 ms)보다 약 9 ms 높은 것은 카메라 캡처 대기·후처리·디스플레이 오버레이 시간이 포함되기 때문입니다.

### ModelZoo NPU 참조값 (STM32N6570-DK, NPU/MCU)

| 모델 | 추론 시간 | Inf/sec |
|------|:---------:|:-------:|
| 192 int8 | 22.05 ms | 45.35 |
| 224 int8 | 27.64 ms | 36.18 |
| **256 int8** | **35.50 ms** | **28.17** |

## 4. 451 ms 병목 원인과 해결

### 원인

| 항목 | 값 |
|------|:--:|
| 문제 텐서 크기 (128×128 활성화) | 1.500 MB |
| npuRAM 단일 뱅크 최대 크기 | 448 KB |
| 배치 위치 (atonn 자동 결정) | hyperRAM (xSPI1) |
| hyperRAM vs 내부 SRAM 대역폭 | 약 1/16 |
| 결과 추론 시간 | ~451 ms (정상의 25×) |

### 해결

| 항목 | 내용 |
|------|------|
| 플래그 | `--enable-virtual-mem-pools` (Neural ART 컴파일러) |
| 원리 | npuRAM3~6 (`0x34200000–0x343C0000`, 1792 KB) 물리적 연속 배치 → 가상 단일 풀로 취급 |
| 추가 옵션 | `--optimization time` (stedgeai 스케줄러가 레이턴시 우선 최적화) |
| 효과 | hyperRAM 사용 1.500 MB → 0 B, 추론 시간 451 ms → ~45 ms |

## 6. 낙상 감지 파이프라인 관점

| 항목 | 192 모델 | 256 모델 (최종) |
|------|:--------:|:--------------:|
| 추론 시간 | ~18 ms | ~45 ms |
| 등가 FPS | ~55 FPS | ~22 FPS |
| 낙상 감지 충분 여부 | 충분 | **충분** |

낙상 이벤트는 100–300 ms 단위로 자세가 변화하므로 ~45 ms(~22 FPS) 수준의 추론 속도는 실용적입니다.
256 모델은 해상도 향상으로 원거리·소형 피사체의 키포인트 정확도가 개선되어 낙상 직전/직후 전신 포즈 품질이 향상됩니다.
